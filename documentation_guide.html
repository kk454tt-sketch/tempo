Part 2: Deep Dive File-by-File Explanation

Below is the complete analysis of every file and directory verified in your actual project.

2.1 Root Configuration & Tooling Files

1. package.json

  • Path: /package.json
  • Simple Explanation: The ID card and blueprint of your project. It lists every external library your website uses, project metadata, and shortcut commands (like npm run dev).
  • Why it exists: Node.js and Vite need to know which libraries to download and how to launch your project.
  • Which part uses it: The entire development workflow, npm, and build tools.
  • Status: Essential.
  • What breaks if modified: Deleting it destroys your project's ability to install packages or run commands. Incorrect edits can cause dependency conflicts.
  • Beginner safety: Do not touch manually unless adding a package via npm install.

2. package-lock.json

  • Path: /package-lock.json
  • Simple Explanation: A detailed security seal that records the exact version of every single file downloaded into node_modules.
  • Why it exists: Ensures that when you or someone else runs npm install on another machine, identical code is installed down to the last digit.
  • Which part uses it: npm during package installation.
  • Status: Generated automatically.
  • What breaks if modified: Inconsistent builds or unexpected version updates across installations.
  • Beginner safety: Never edit this file by hand. Leave it alone.

3. vite.config.ts

  • Path: /vite.config.ts
  • Simple Explanation: The control center for Vite. It activates the React plugin, sets the local port to 3000, creates the @/ alias pointing to src/, and injects the tempoBackendPlugin() middleware so requests to /api connect directly to your local database without running a separate server process.
  • Why it exists: Configures bundling rules and local server behavior.
  • Which part uses it: Vite dev server and build pipeline.
  • Status: Essential.
  • What breaks if modified: The local website will stop loading, paths starting with @/ will fail, and API calls to /api will return 404 errors.
  • Beginner safety: Do not change unless specifically instructed to adjust port or proxy settings.

4. tailwind.config.js & postcss.config.js

  • Path: /tailwind.config.js, /postcss.config.js
  • Simple Explanation: Custom styling configuration. Contains custom color palettes (e.g. coral, brand), animations, and font settings. PostCSS ensures vendor prefixes are added for cross-browser compatibility.
  • Why it exists: Allows you to write utility classes like bg-brand-500 and compiles them into pure CSS.
  • Which part uses it: Every component and page styled with Tailwind.
  • Status: Essential.
  • What breaks if modified: All custom colors, rounded corners, and animations across your website will revert to default or look broken.
  • Beginner safety: Safe to leave alone. Only edit when you want to add new theme colors.

5. tsconfig.json & tsconfig.node.json

  • Path: /tsconfig.json, /tsconfig.node.json
  • Simple Explanation: Rules for TypeScript compiler. Tells TypeScript how strictly to verify your code and how to resolve imports like @/components/....
  • Why it exists: Enforces code health and type safety across your React components.
  • Which part uses it: VS Code editor and the tsc build step.
  • Status: Essential.
  • What breaks if modified: VS Code will show red underline errors everywhere, and npm run build will fail.
  • Beginner safety: Leave completely alone.

6. index.html

  • Path: /index.html
  • Simple Explanation: The master web page frame. Contains the <div id="root"></div> where React mounts the entire application, loads Google Fonts (Inter, Playfair Display), and has the script tag loading /src/main.tsx.
  • Why it exists: Browsers only load HTML files directly. Vite uses this as its entry gate.
  • Which part uses it: The browser entry point.
  • Status: Essential.
  • What breaks if modified: Deleting the #root div causes a completely blank white screen.
  • Beginner safety: Safe to leave alone, or edit only to update the <title> tag or favicon.

7. .env & .env.example

  • Path: /.env, /.env.example
  • Simple Explanation: Secret key configuration. Contains sensitive credentials such as your Supabase Project URL and Anonymous Public Key. .env.example is a blank template showing what variables are required.
  • Why it exists: Prevents hardcoding secret keys inside code files.
  • Which part uses it: src/services/supabase.ts via import.meta.env.
  • Status: Essential.
  • What breaks if modified: Supabase authentication and database cloud storage will fail to connect.
  • Beginner safety: Keep your .env file private. Never share it publicly or upload it to GitHub.

8. firebase.json & .firebaserc / vercel.json

  • Path: /firebase.json, /.firebaserc, /vercel.json
  • Simple Explanation: Deployment routing configs. They tell Firebase Hosting or Vercel to route all web traffic to index.html so React Router can handle pages on reload.
  • Why it exists: Prevents 404 Not Found errors when refreshing sub-pages on production hosts.
  • Which part uses it: Cloud hosting providers when deployed.
  • Status: Used by the project (for deployment).
  • What breaks if modified: Direct URL visits to /dashboard on deployed hosts would fail.
  • Beginner safety: Leave alone.

Part 5: AI Token-Saving Guide

5.1 Understanding Tokens: The Fuel of AI

AI models do not read files as traditional text or words; they read chunks of characters called Tokens (roughly 1 token ≈ 4 characters or 0.75 words in English). Everything exchanged with the AI has a token cost:

  • Input Tokens: Every single word in your prompt PLUS every file or snippet you attach. Pasting your whole project consumes massive input tokens on every turn.
  • Context Window: The AI's working memory limit. As your conversation gets longer, older messages and large pasted files accumulate, causing the AI to become sluggish, lose focus, or hallucinate.
  • Output Tokens: The code and text the AI writes back to you. Generating full 500-line files consumes heavy output tokens and takes much longer to complete.

5.2 The 10 Golden Rules to Save 80% of AI Tokens

Rule 1: Never Paste Entire Files When Changing Small Sections

If you want to modify a button in WebsiteCreatorPage.tsx (which is 1,200+ lines long), do not paste all 1,200 lines. Paste only the button JSX and its handler function (approx. 20 lines). This saves over 95% of your tokens.

Rule 2: Ask for Diffs or Targeted Snippets, Not Full File Rewrites

Tell the AI: "Show me only the modified function or a standard Git diff. Do not rewrite the entire file." This drastically cuts output tokens.

Rule 3: Have AI Diagnose Root Causes Before Writing Code

Instead of saying "My payments are broken, rewrite my payment code", ask: "Here is the error message: [paste error]. What are the top 2 possible root causes in my logic?" Fix the diagnosis first, then write 5 lines of code instead of 300.

Rule 4: Use VS Code Search to Find the Exact Needle

Press Ctrl + Shift + F to search for the specific button text or class name. Find the exact 10 lines responsible, and provide only those lines to the AI.

Rule 5: Reuse Existing UI Components Instead of Creating New Ones

Your codebase already has Button.tsx, Modal.tsx, Input.tsx, and Badge.tsx in src/components/common/. Tell AI: "Use my existing Button and Modal components from @/components/common/ rather than creating new custom elements."

Rule 6: Maintain a Concise System Context Note

Instead of explaining your entire tech stack every time, use a two-line summary: "React 18 + Vite + TypeScript + Tailwind CSS. Path alias '@' points to '/src'."

Rule 7: Request 'Explanation Only on Request'

Tell the AI: "Be concise. Return only the updated snippet and a 1-sentence summary of why it solves the problem." This saves hundreds of conversational output tokens.

Rule 8: Inspect Imports Before Writing Duplicate Helper Utilities

Check src/utils/. You already have cn.ts, formatting.ts, and countdown.ts. Reusing them keeps your codebase clean and token spend low.

Rule 9: Start Fresh AI Conversations for Unrelated Tasks

Do not keep a single chat open for weeks. Once a feature is done, start a new chat so previous conversations do not count against your input token quota.

Rule 10: Use Terminal Commands to Filter Bug Information

Instead of pasting 500 lines of terminal logs, copy only the top 5 lines of the error stack trace showing the filename and line number.

Part 6: Ready-to-Use AI Prompts

Copy and paste these battle-tested, token-efficient prompt templates directly into Gemini or your AI assistant.

Prompt 1: Understanding an Unfamiliar File
"Explain the purpose of [FILENAME] in 3 bullet points: 1) What it does, 2) Which other files depend on it, and 3) Whether it is safe for a beginner to modify. Keep your answer under 100 words."
Why it saves tokens: Limits output length strictly and prevents long generic lectures.
Prompt 2: Finding Files Responsible for a Feature
"In my React+Vite project, I want to modify [FEATURE NAME, e.g. the RSVP WhatsApp share button]. Which file and function contains this logic? List only the file paths and line ranges."
Why it saves tokens: Produces an instant roadmap without generating unnecessary code.
Prompt 3: Fixing a Bug Without Rewriting Everything
"Here is the error message from my terminal: [PASTE ERROR]. Below is the relevant 15-line function from [FILENAME]: [PASTE FUNCTION]. What is the root cause? Return only the corrected lines to replace."
Why it saves tokens: Targets only the broken lines, avoiding entire file regenerations.
Prompt 4: Adding a Feature with Existing Components
"I want to add a [NEW FEATURE, e.g. confirmation popup] to [FILENAME]. Use my existing Modal and Button components from '@/components/common/'. Show only the import line and the new JSX snippet."
Why it saves tokens: Prevents AI from generating duplicate modal components or huge files.
Prompt 5: Finding Potentially Unused Files Safely
"I am auditing my project to remove clutter. Check if [FILENAME] is imported anywhere in 'src/' or referenced in configs. Answer with either 'ACTIVE' or 'CANDIDATE FOR CLEANUP' and a 1-sentence reason."
Prompt 6: Asking AI to Explain Proposed Changes First
"Before writing any code, outline your proposed plan in 3 steps to implement [CHANGE]. Do not write the code yet. Wait for my approval."
Why it saves tokens: Prevents generating large amounts of incorrect code that has to be discarded.

9.2 Beginner Glossary of Terms

  • Component: A self-contained, reusable piece of user interface (like a Navbar, Button, or Card) written in React.
  • Vite: The ultra-fast development server and asset packager that runs your local website.
  • HMR (Hot Module Replacement): Vite's feature that instantly updates changes in your browser without requiring a full page refresh.
  • Props: Arguments passed into a React component (like passing a title or button color).
  • State: Internal component memory that triggers a screen re-render whenever its value changes (e.g. text typed in a form).
  • Context: Global memory shared across the entire website (like user login state) without having to pass props through every component level.
  • Tailwind CSS: A styling system that lets you design directly inside HTML tags using utility classes like text-lg font-bold p-4.
  • SQLite (tempo.db): A lightweight, file-based database that stores your website data locally on your computer without needing complex server setups.
